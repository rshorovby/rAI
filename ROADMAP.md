# RallyMind — Product & Engineering Roadmap

**Версия:** 1.0 · **Дата:** 26 июля 2026  
**Источник целей:** RallyMind RU Angel Deck — Investor V9 Final (июль 2026)  
**Горизонт:** 18 месяцев раунда + видение до 2031  
**Продукт сегодня:** Telegram-бот `@RallyCoachAI_bot` (Live MVP)  
**Продукт на выходе:** экосистема «память игрока» — Telegram + iOS + Android + Coach/Club web

---

## 1. Что мы строим (тезис из деки, переведённый в инженерию)

> «Другие анализируют сессию. RallyMind помнит игрока.»

Из этого следует главное архитектурное требование: **ядро продукта — не video-pipeline, а персистентная модель игрока**. Разбор ролика — лишь событие, которое обновляет эту модель.

| Тезис деки | Инженерное следствие |
| --- | --- |
| Память игрока между играми | Долговременное хранилище сессий, ошибок, фокусов; версионирование прогресса |
| Снял → понял → запомнил | Замкнутый цикл: capture → analysis → focus → проверка на следующем видео |
| Методика Ани как moat | Слой знаний (`knowledge/`) + human-in-the-loop правки → дообучение промптов |
| Тренер получает инструмент | Мультиролевая модель: player / coach / club, доступ к чужой истории |
| Telegram-first, потом mobile | Backend должен перестать быть частью бота |
| 3 спорта / 6 рынков к 2031 | Мультиспорт и i18n как параметры, не форки |

**Немедленный вывод:** до мобильных приложений обязателен **вынос backend из монолита бота**. Иначе iOS/Android придётся писать против Telegram-хендлеров.

## 3. Целевая архитектура

### 3.1. Сегодня

```
Telegram → bot.py (монолит: UI + логика + AI + БД) → Gemini
                          ↓
                    SQLite на droplet
```

### 3.2. Целевая (к концу фазы P1)

```
        Telegram bot ─┐
        iOS app ──────┼──→  RallyMind API (FastAPI)  ──→  Postgres
        Android app ──┤            │                        (player memory)
        Coach web ────┘            ├──→ Job queue → Workers
                                   │        ├─ video preprocess (mute/trim)
                                   │        ├─ MediaPipe pose
                                   │        └─ Gemini analysis
                                   └──→ Object Storage (видео, overlay)
```

**Принципы миграции:**

1. **Strangler pattern.** Логика по одному домену выносится из `bot.py` в сервисный слой; бот становится тонким клиентом API. Никакого «большого переписывания».
2. **Контракт раньше клиента.** OpenAPI-схема фиксируется до старта iOS.
3. **Telegram остаётся first-class каналом**, а не legacy — это точка входа с нулевым трением.
4. **Один источник правды по игроку.** Мобильное приложение и бот пишут в одну модель памяти.

## 4. Фазы

Фазы синхронизированы с вехами раунда из деки: **200 → 1 500 → 5 000 платящих**.

### P0 · Месяцы 1–4 — «MVP, который берёт деньги»

**Цель раунда:** 200 платящих · D30 ≥ 35% · 4+ разбора/мес.  
**Продуктовая гипотеза:** люди платят за память и фокус, а не за разовый разбор.

| Блок | Задачи | Definition of done |
| --- | --- | --- |
| Монетизация | Telegram Stars и/или веб-чекаут; тарифы Free/Pro; grace-периоды | Пользователь платит и получает Pro-лимиты без ручных действий |
| Квоты | Лимит разборов Free (1–2/мес), fair-use Pro, лимит длины видео | Перерасход невозможен без апгрейда |
| Cost-телеметрия | `usage_metadata` в `events`: input/output/thinking tokens, длина видео, модель | Отчёт «cost за 30 дней» и cost на разбор — фактический, не оценочный |
| Память игрока v2 | Оценки 3–4 навыков в каждом разборе; «фокус недели»; сравнение с прошлой игрой | Экран/сообщение «стало ли лучше» работает на реальных данных |
| Drills v1 | 30–50 упражнений с тегами проблем, `telegram_file_id`; выдача по итогам разбора | Разбор всегда завершается конкретным упражнением |
| Retention-петля | Напоминания, недельный дайджест, стрики | D30 измеряется и растёт |
| Надёжность | Sentry/алерты, ретраи Gemini, graceful degradation | Падение внешнего API не рвёт UX |

**Технический долг, который гасим здесь:** сессия диалога в `context.user_data` (теряется при рестарте) → переносится в БД.

**Метрики выхода:** 200 платящих; D30 ≥ 35%; фактический cost/разбор подтверждён телеметрией; ≥ 4 разбора на платящего в месяц.

---

### P1 · Месяцы 5–9 — «Backend + iOS + тренер»

**Цель раунда:** 1 500 платящих · $22.5K MRR · работающий канал тренеров.

| Блок | Задачи | Definition of done |
| --- | --- | --- |
| API-слой | FastAPI, OpenAPI-контракт, JWT/OAuth, миграция логики из `bot.py` | Бот работает через тот же API, что и мобильное приложение |
| Postgres | Миграция SQLite → Postgres, alembic, бэкапы | Конкурентная запись, >10k MAU без блокировок |
| Очередь и воркеры | Celery/RQ или arq; отдельные воркеры под pose и Gemini | Пики видео не блокируют бота; видимый статус обработки |
| Object Storage | S3-совместимое хранилище видео/overlay с TTL | Видео и скелет доступны в приложении, а не только в чате |
| **iOS-приложение** | Съёмка/выбор видео, загрузка, отчёт, история, прогресс, подписка | App Store релиз; фича-паритет с ботом + графики прогресса |
| Coach console (web) | Список учеников, AI-черновик разбора, правка тренером, отправка ученику | Тренер выпускает разбор быстрее, чем писал бы вручную |
| Методический loop | Правки Ани/тренеров сохраняются как обучающие пары к промптам | Накопление проприетарных данных, измеримое качество |

**Почему iOS первым:** компетенция основателя (10+ лет iOS), выше платёжеспособность аудитории, App Store как канал доверия.

**Развилка (решить до старта):** нативный Swift vs кроссплатформа.  
Рекомендация — **нативный iOS**, потому что: камера/видео-пайплайн, качество UX как часть позиционирования, и это самая быстрая дорога именно для этой команды. Android в P2 — отдельно, по стабилизированному контракту API.

**Метрики выхода:** 1 500 платящих; $22.5K MRR; ≥ 20% выручки приходит не из Telegram; ≥ 10 активных тренеров.

### P2 · Месяцы 10–18 — «Android, клубы, масштаб»

**Цель раунда:** 5 000 платящих · $75K MRR · $0.9M ARR · готовность к следующему раунду.

| Блок | Задачи | Definition of done |
| --- | --- | --- |
| **Android-приложение** | Паритет с iOS по контракту API | Google Play релиз |
| Club / branded plans | Организации, команды, брендирование, места для тренеров | Первые клубы платят по B2B-договору |
| Pose v2 | Углы суставов в промпт (колени на подаче, точка контакта) | Отчёт содержит измеренные величины, не только описание |
| RAG по `knowledge/` | Embeddings и поиск вместо статичной подмешки wiki | Точность растёт при росте базы знаний |
| Cost-оптимизация | Роутинг Flash/Pro, context caching, лимиты длины | Cost/разбор снижается при росте объёма |
| Инфраструктура | Мониторинг, автоскейл воркеров, SLO | Обработка стабильна на 30k+ MAU |
| Данные | Датасет разборов с правками тренеров, оценка качества | База для собственной модели в будущем раунде |

**Метрики выхода:** 5 000 платящих; $75K MRR; unit-экономика подтверждена когортами; продукт готов к географической экспансии.

### P3 · 2028–2031 — «Мультиспорт и рынки»

Из деки: 225M+ игроков, теннис + падел + пиклбол, 6 рынков, AI-слой $37B.

| Направление | Содержание |
| --- | --- |
| Падел и пиклбол | Спорт как параметр: своя wiki, свои промпты, свои drills; общий движок памяти |
| Локализация | Языки поверх готового `i18n`; методика адаптируется под рынок |
| Собственная модель | Fine-tune на накопленном датасете; **только здесь появляется GPU-статья расходов** |
| Платформа для тренеров | Маркетплейс, white-label, интеграции с клубными системами |

## 5. Ключевые технические решения

| Решение | Выбор | Обоснование |
| --- | --- | --- |
| Backend framework | FastAPI (Python) | Переиспользуем весь текущий код анализа |
| БД | Postgres (managed) | Конкурентность, аналитика, бэкапы |
| Очередь | Redis + arq/Celery | Видео — долгие задачи, нужен статус и ретраи |
| Мобильные | Нативные iOS → Android | Камера, UX, компетенция команды |
| Coach console | Web (React) | Быстрее, чем нативные админки |
| AI | Gemini API, роутинг Flash/Pro | Без GPU до P3 |
| Pose | MediaPipe на CPU | Дёшево, работает, GPU не требуется |
| Платежи | Telegram Stars + web-чекаут + App/Play | Комиссии различаются — влияет на экономику |

**Осознанное решение об оплате:** магазины берут 15–30%, Telegram Stars — свою комиссию, веб-чекаут дешевле всего. Смешанная схема с приоритетом веб-чекаута прямо влияет на маржу (см. финансовый документ).

## 6. Риски и как мы их снимаем

| Риск | Влияние | Митигация |
| --- | --- | --- |
| Монолит бота тормозит мобильные приложения | Срыв вехи мес. 9 | API-слой начинается в P1 сразу, до iOS-кода |
| Зависимость от Gemini (цена, лимиты, политика) | COGS и приватность | Абстракция провайдера, роутинг моделей, контроль длины видео |
| Комиссии магазинов | Минус 15–30% выручки | Приоритет веб-чекаута; в мобильных — подписка вне магазина, где допустимо |
| CAC выше плана | Не хватает раунда | Канал тренеров/клубов как органический источник; см. чувствительность в фин. модели |
| Churn выше 12% | Ломается LTV/CAC | Retention-петля (фокус недели, стрики, дайджест) — приоритет P0, не P2 |
| Качество разбора не убеждает | Нет конверсии | Human-in-the-loop правки Ани, метрика полезности после каждого отчёта |
| Пиковая нагрузка на видео | Таймауты | Очередь + воркеры + прозрачный статус в UI |
